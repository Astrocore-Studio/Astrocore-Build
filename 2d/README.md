# Astrocore 2D — Relay Two

Нативный 2D-клиент и сервер используют `astrocore-grid2d` из соседнего
чекаута `Astrocore-Engine`. Сборка использует корневой workspace и
`Cargo.lock` Astrocore Build.

Запустите локальный сервер и клиент из корня `Astrocore-Build`:

```bash
cargo play
```

Для одиночного запуска команда выбирает свободный локальный UDP-порт и
создаёт ключ сеанса. Для игры с несколькими клиентами задайте один общий
ключ из 64 шестнадцатеричных символов в `ASTRO_2D_KEY` и одинаковый адрес в
`ASTRO_2D_ADDR` во всех терминалах. Запустите отдельный сервер командой
`cargo serve2d`, затем откройте один или несколько клиентов командой
`cargo client2d`. При отдельных запусках адрес по умолчанию —
`127.0.0.1:7782`. Для открытия окна клиенту нужен дисплей.

Соберите сервер и клиенты из одной пары ревизий Engine и Build. При входе
клиент получает карту, каталог прототипов и актуальный снимок раунда с сервера.
Дальше сервер передаёт изменения состояния. После длительного пропуска
обновлений клиент получает новый полный снимок.

В активном раунде выделенный пул Rayon рассчитывает атмосферу параллельно с
расчётом питания в потоке сервера. Вентиляция и дыхание используют результаты
обоих расчётов. Число потоков в пуле можно задать через `RAYON_NUM_THREADS`.

В Bash можно сгенерировать новый ключ командой
`export ASTRO_2D_KEY="$(openssl rand -hex 32)"`.

В лобби выберите профессию клавишей с её номером и подтвердите готовность
клавишей Enter. При подтверждении сервер резервирует место. Клавиша O
переводит в режим наблюдения и освобождает резерв. Раунд начинается, когда
хотя бы один игрок готов, а остальные готовы или наблюдают. Наблюдатели могут выбрать
профессию и войти в текущий раунд, если есть место. При подключении посреди
раунда клавиша Enter назначает выбранную профессию. Раунд заканчивается
после выполнения общей задачи, по таймеру или при потере всего экипажа.
После подведения итогов сервер восстанавливает карту и возвращает экипаж
в лобби.

На Relay Two оператор получает газоанализатор и рюкзак, инженер — строительный
набор и рюкзак, медик — перевязочный пакет и средство от удушья. Снаряжение
выдаётся на старте раунда согласно `loadouts` в карте.

В `station.ron` раздел `jobs` задаёт число мест и точки появления профессий.
При отсутствии настроек доступность не ограничена, а игра использует общие
точки появления `spawns`. Занятое место освобождается при отключении.

```ron
jobs: {
    "Medic": (slots: Some(1), spawns: [(x: 8, y: 5, z: 0)]),
},
```

Проверка свободного места при назначении и позднем входе основана на
`ServerStationJobsSystem` из NightCity.
[NightCity ServerStationJobsSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Station/Systems/ServerStationJobsSystem.cs)

### Восстановление отсека

1. Включите резервный генератор в левом отсеке на клетке (4, 3), чтобы подать питание на шлюзы и вентиляцию.
2. Откройте шлюзы. Пройдите в правый отсек и закройте за собой шлюз, чтобы изолировать левый отсек.
3. Заделайте пробоину на восточной стене (20, 7) инженерным набором и включите подачу воздуха из резерва (16, 5). Резерв ограничен.
4. Следите за прогрессом вверху экрана. Экипаж побеждает, когда при герметичном корпусе и работающей вентиляции давление в контрольной точке держится от 82 кПа три секунды, а кислорода достаточно для дыхания.

| Клавиша | Действие |
| --- | --- |
| WASD или стрелки | Двигаться |
| E | Подобрать ближайший предмет или переключить устройство |
| X | Сменить активную руку |
| Q | Положить предмет из активной руки на пол |
| F | Использовать предмет в активной руке на себе. Газоанализатор показывает давление, долю кислорода и температуру |
| G | Лечить или сканировать напарника в соседней клетке под курсором |
| T | Взять пострадавшего под курсором на буксир или отпустить его |
| H | Передать предмет в свободную активную руку напарника в соседней клетке под курсором |
| I | Открыть или закрыть инвентарь |
| Page Up / Page Down | Подняться или спуститься, стоя на отметке перехода ↕ |
| Щелчок по подписи руки | Выбрать пустую руку, переложить предмет в пустую активную руку или использовать предмет в активной руке |
| B | Поставить стену под курсором с инженерным набором в активной руке |
| N | Уложить пол в пустой клетке под курсором с инженерным набором |
| V | Разобрать стену или пол под курсором с инженерным набором |
| C | Уложить кабель на полу под курсором с мотком в активной руке |
| R / Shift+R / Ctrl+R | Снять под курсором кабель LV / MV / HV кусачками |
| P | Измерить давление в трубе под курсором газоанализатором |
| J | Проверить заряд, вход и выход соседнего накопителя под курсором |

Возьмите рюкзак в активную руку, откройте инвентарь и нажмите Equip. Кнопка
Store held item кладёт предмет из активной руки в свободную ячейку рюкзака.
Щелчок по предмету достаёт его в пустую активную руку. Кнопка Remove снимает
рюкзак в пустую активную руку. Содержимое сохраняется, когда рюкзак лежит на полу.

### Электросети

На Relay Two генератор соединён с подстанцией в (5, 4) высоковольтным
кабелем HV. Подстанция питает APC в (5, 6) по сети MV. От APC идёт сеть LV
через накопитель в (6, 5) к шлюзам и вентиляции. Кабели разных напряжений
могут лежать в одной клетке. Подстанция и APC передают энергию между
соответствующими сетями.
[NightCity Substation](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Resources/Prototypes/Entities/Structures/Power/substation.yml)
[NightCity APC](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Resources/Prototypes/Entities/Structures/Power/apc.yml)

Моток LV лежит в (4, 4), MV в (3, 5), HV в (3, 4), кусачки в (5, 4).
Кусачки показывают кабели всех напряжений текущего этажа, а моток показывает
кабель своего напряжения. Укладка расходует одну секцию. Снятие занимает
секунду и оставляет на полу секцию того же напряжения. Движение или смена
инструмента прерывают снятие. Сервер пересчитывает питание после изменения
схемы, а следующий раунд восстанавливает исходную раскладку.
[NightCity Cable prototypes](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Resources/Prototypes/Entities/Structures/Power/cables.yml)
[NightCity CableSystem.Placer](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Power/EntitySystems/CableSystem.Placer.cs)
[NightCity CableSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Power/EntitySystems/CableSystem.cs)

Накопитель заряжается от входной сети. При отключении входа он питает
выходную сеть, пока хватает заряда. Заряд сохраняется при снятии и укладке
кабелей. Клавиша J показывает запас энергии в джоулях и мощность каждого
порта на момент осмотра. Если кабели соединяют оба порта напрямую, накопитель
отключается от цепи и сохраняет запас.
[NightCity SMES](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Resources/Prototypes/Entities/Structures/Power/smes.yml)

Закрытый шлюз герметичен и
остаётся закрытым без питания. Открытый шлюз нельзя закрыть, пока проём
занят. Правый отсек сообщается с вакуумом через пробоину корпуса. Клиент
показывает давление и накопленный урон. При отключении игрока его предметы
остаются на полу.

### Трубопроводы

В левом отсеке Relay Two баллон соединён трубами с пассивной вентиляцией
через ручной клапан в клетке (5, 8). Встаньте рядом и нажмите E, чтобы
открыть или закрыть клапан. С газоанализатором в активной руке наведите курсор
на клапан и нажмите P. Показания идут сначала со стороны, куда направлен
клапан, затем с противоположной. Клавиша F измеряет воздух в помещении.
Газ распределяется по соединённым узлам. Закрытый клапан разделяет сеть и
сохраняет газ в каждой части. Пассивная вентиляция выравнивает давление
между трубой и помещением. Новый раунд восстанавливает исходное положение
клапанов и заправляет баллоны.
[NightCity GasValveSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Binary/EntitySystems/GasValveSystem.cs)
[NightCity GasPassiveVentSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Unary/EntitySystems/GasPassiveVentSystem.cs)

Рядом есть контур с насосом давления (8, 7) и нагнетателем (9, 7).
Включите резервный генератор и переключите каждый прибор клавишей E.
Насос поднимает давление на выходе, нагнетатель подаёт газ в помещение
до заданного давления. Скруббер (9, 6) отводит примеси в отдельную трубу.
Газоанализатор по P показывает давление и состояние питания. У насоса
он выводит значения на выходе и входе. Обрыв кабеля останавливает
перенос газа. После ремонта включённый прибор продолжает работу.
[NightCity GasPressurePumpSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Binary/EntitySystems/GasPressurePumpSystem.cs)
[NightCity GasVentPumpSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Unary/EntitySystems/GasVentPumpSystem.cs)
[NightCity GasVentScrubberSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Unary/EntitySystems/GasVentScrubberSystem.cs)

Газовый фильтр в клетке (9, 2) делит смесь из баллона между двумя выходами.
Наведите на него курсор, стоя рядом, и нажмите U. Пробел включает или выключает
фильтр, стрелки влево и вправо выбирают газ, стрелки вверх и вниз меняют расход
от 0 до 1000 л/с с шагом 100 л/с. Выбранный газ уходит в боковой порт, остальная смесь
идёт через прямой выход. Без выбранного газа вся смесь идёт прямо. Фильтр
работает без кабеля. Клавиша P с газоанализатором показывает давление на всех
трёх портах и долю выбранного газа. Новый раунд восстанавливает настройки
из RON.
[NightCity GasFilterSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Server/Atmos/Piping/Trinary/EntitySystems/GasFilterSystem.cs)

### Медицина

Недостаток кислорода вызывает удушье. Давление до 20 кПа также вызывает
тупую травму. Суммарный урон от 100 до 199 переводит персонажа в критическое
состояние, а с 200 он погибает. Критическое состояние блокирует управление.
Напарник может оказать помощь.

Для эвакуации освободите одну руку, встаньте рядом с пострадавшим и нажмите
T. Он следует за вами с учётом стен и закрытых шлюзов. У перехода на другой
этаж подтяните его к отметке ↕ и поднимитесь или спуститесь обычной клавишей.
Повторное нажатие T отпускает пострадавшего. Захват снимается при возвращении
пациента в сознание. Проверки рук и остановки при потере сознания опираются
на `PullingSystem` из NightCity.
[NightCity PullingSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Shared/Movement/Pulling/Systems/PullingSystem.cs)

Одна доза перевязочного пакета снимает 5 единиц тупого урона. В пакете 10 доз,
применение занимает три секунды. Средство от удушья снимает урон от
недостатка кислорода. Пациент возвращается в сознание, когда суммарный урон
опускается ниже 100. Во время лечения участники удерживают позицию, а
лечащий держит выбранный предмет в активной руке. Движение, смена предмета,
закрытие преграды или уход участника прерывают лечение. Предмет расходуется
при успешном завершении. Лечение себя занимает вдвое больше времени.

Ручной анализатор здоровья лежит на Relay Two в клетке (6, 5). Он показывает
значения тупой травмы и удушья на момент завершения сканирования.

Ограничения лечения по видам урона, задержка и проверка активной руки
основаны на `HealingSystem` из NightCity. Встроенные медицинские прототипы
задают эффекты для двух поддерживаемых видов урона. Карты с прежним полем
`Item(healing: …)` продолжают загружаться, такой предмет лечит общий урон.
[NightCity HealingSystem](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Content.Shared/Medical/Healing/HealingSystem.cs)

Инженерный набор лежит в левом отсеке. Строить и разбирать можно в соседней
клетке. Строительство расходует запас набора, разборка возвращает материал.
Сервер проверяет занятость клеток и защищает кабели, точки появления и
устройства. Разборка стены корпуса открывает отсек вакууму. Новая стена
закрывает пробоину. Укладка пола сама по себе воздух не добавляет.

Встроенная станция находится в `content/station.ron`, прототипы разложены
по игровым системам в `content/prototypes/`. Чтобы загрузить другой комплект,
задайте серверу `ASTRO_2D_CONTENT` с путём к его каталогу. Строки карты
идут сверху вниз. `.` обозначает пол, `#` стену, `~` космос. В координатах
размещений ось Y растёт вверх от нижней строки.

### Наследование прототипов

Сервер и редактор рекурсивно загружают файлы `*.ron` из `prototypes/` рядом со
`station.ron`. В каждом файле хранится словарь прототипов. Если в том же
каталоге есть старый `prototypes.ron`, его записи входят в общий реестр.

Прототип может заполнять поля `name`, `kind` и `color`
из записей, указанных в `parents`. Значение потомка имеет приоритет. Если
потомок пропустил поле, берётся первое значение из списка родителей.
Параметр `kind` наследуется как единое значение. Объекты с `abstract: true`
служат шаблонами и отсутствуют в палитре редактора. Для объектов, которые
можно разместить, все три поля должны быть известны после наследования.

```ron
{
    "base_pipe": (abstract: true, color: (114, 169, 149)),
    "air_pipe": (parents: ["base_pipe"], name: "Straight pipe", kind: Piping(Straight)),
}
```

Родители и потомки могут находиться в разных файлах. Порядок объявлений
произвольный. Цикл, отсутствующая ссылка и повтор идентификатора останавливают
загрузку с указанием проблемного прототипа. Клиент получает готовые
определения.
[Robust Toolbox SerializationManager.Composition](https://github.com/space-wizards/RobustToolbox/blob/1afd6929b473dd537b42cb668a961c84a2e2e7c6/Robust.Shared/Serialization/Manager/SerializationManager.Composition.cs)

#### Перенос медицинских прототипов из YAML в RON

Передайте конвертеру путь к каталогу с исходными YAML-прототипами и их
родительскими шаблонами. Список `selection.ron` связывает новый идентификатор
с полем `id` сущности в YAML и задаёт цвет объекта в редакторе. Поле `name`
можно указать явно или получить из исходного прототипа.

```ron
[
    (id: "field_dressing_single", source: "Brutepack1",
     name: Some("Single field dressing"), color: (214, 144, 206)),
]
```

```bash
cargo run --locked --features prototype-import --bin astrocore-2d-import-prototypes -- \
    "$source_prototypes" selection.ron > imported-medical.ron
```

Переместите результат в `prototypes/medical/` рабочего комплекта контента.
Сервер и редактор читают сгенерированный RON. Конвертер обрабатывает
одиночного родителя и списки родителей в YAML. Поля компонентов объединяются
с приоритетом потомка, затем родителей в порядке объявления.

Конвертер переносит целые отрицательные значения из `Healing.damage.types.Blunt`
и `Healing.damage.types.Asphyxiation`. `Healing.delay` округляется вверх
до целого тика, по умолчанию три секунды. `Stack.count` задаёт от 1 до 255
применений, по умолчанию одно. Перевязочный пакет в `medical/treatment.ron`
использует параметры тупой травмы и число применений из `Brutepack`.
[NightCity Brutepack](https://github.com/NightCity2045/space-station-14/blob/366c3c13cab39c3ccf22fba75eb9a3af2a6e7cb7/Resources/Prototypes/Entities/Objects/Specific/Medical/healing.yml#L115)
[SS14 HealingComponent](https://github.com/space-wizards/space-station-14/blob/2f4a2aad293c1e43f2a2ca673333f7dddb2b9b6d/Content.Shared/Medical/Healing/HealingComponent.cs)
[Медицинские прототипы SS14](https://github.com/space-wizards/space-station-14/blob/2f4a2aad293c1e43f2a2ca673333f7dddb2b9b6d/Resources/Prototypes/Entities/Objects/Specific/Medical/healing.yml)

### Этажи карты

Поле `grid` задаёт этаж Z = 0. Дополнительные этажи задаются словарём `levels`,
где ключом служит целый номер Z, например `-1` или `1`, а значением служат
строки этажа в том же формате. Размер каждого этажа ограничен 64 × 64 тайлами.
Координаты без поля `z` относятся к этажу 0. В `links` указываются пары
клеток пола на соседних этажах, от нижней к верхней.

```ron
links: [
    (lower: (x: 4, y: 5, z: -1), upper: (x: 4, y: 5, z: 0)),
],
```

Клиент показывает этаж персонажа. Через переходы проходит воздух. Обычные
взаимодействия, строительство и соединение соседних кабелей учитывают Z.

## Редактор карт

Откройте рабочую копию контента из корня `Astrocore-Build`.

```bash
station_dir="$(mktemp -d)"
cp -r 2d/content/. "$station_dir/"
cargo editor2d "$station_dir"
```

Клавиши 1–3 выбирают пол, стену и космос, 4 — точку появления, 5 — кабель,
6 — объект. Кисть 8 ставит точку появления профессии. С кистью кабеля Tab
переключает напряжение LV, MV, HV. С кистью 8 Tab перебирает профессии,
в обычном режиме он перебирает прототипы. Левая кнопка мыши рисует выбранной
кистью, правая стирает. Z отменяет действие, Y повторяет его, F2 сохраняет.
Page Up и Page Down переключают этаж. Вместе с Shift они создают смежный
этаж, если его ещё нет. Для перехода выберите кисть 7 и щёлкните по двум
клеткам пола на смежных этажах. Esc отменяет выбор первой клетки. Правая
кнопка на отметке с кистью 7 удаляет переход.

Кисть объекта размещает трубы, клапаны, баллоны и станционные устройства.
Клавиша R поворачивает выбранную деталь на 90° по часовой стрелке. Повторный
щелчок той же деталью обновляет ориентацию установленной. Соседние детали
соединяются встречными портами на одном этаже. В `station.ron` ориентация
задаётся полем `facing`, по умолчанию `East`. У прямой трубы и клапана второй
порт смотрит в противоположную сторону, у изгиба второй порт повёрнут на 90°
по часовой стрелке. Порты тройника идут вдоль прямой и на 90° по часовой
стрелке. У насоса и газового фильтра сторона `facing` задаёт прямой выход.
У фильтра вход расположен напротив, боковой порт повёрнут на 90° по часовой
стрелке. У варианта `gas_filter_mirrored` боковой порт повёрнут на 90° против
часовой стрелки. Баллоны, нагнетатели, скрубберы и пассивная вентиляция имеют
один порт. Для насоса, нагнетателя и скруббера проложите кабель на их клетках.
Поле `starts_off` задаёт положение
переключателя в начале раунда. Скруббер с `siphoning: true` откачивает всю
смесь в трубу. Обычный режим отводит только примеси из списка фильтра.
Прототипы берутся из каталога `prototypes/`. Если комплекту ещё не задан
`station.ron`, редактор открывает пустую сетку с точкой появления.

В карте `cables` задаёт кабели LV, `medium_cables` задаёт MV, а `high_cables`
задаёт HV. У прототипов генератора и мотка поле `voltage` принимает
`Apc`, `Medium` или `High`. По умолчанию используется `Apc` для LV.

У накопителя параметры `ports.input` и `ports.output` задают напряжения
портов. Для разных напряжений проложите оба кабеля на клетке устройства.
При одинаковом напряжении вход и выход занимают противоположные соседние
клетки, а `facing` указывает на выход. Параметры `capacity_joules`
и `initial_joules` задают ёмкость и начальный заряд.
`charge_watts` задаёт скорость пополнения запаса, `supply_watts` задаёт
доступную мощность разряда. Новый раунд восстанавливает заряд из RON.

Редактор перед записью проверяет карту тем же загрузчиком, что сервер.
После сохранения запустите сервер с `ASTRO_2D_CONTENT="$station_dir"`,
чтобы сыграть на сохранённой карте.
