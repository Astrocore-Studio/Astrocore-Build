# ADR-0013. Разум игрока

Дата: 2026-11-27. Статус: принято (фаза 6, задача 6.5). Заменяет пункт 4 ADR-0012.

## Контекст

До 6.5 связь игрока с телом хранила таблица «пользователь → тело» в `GameTicker`
(ADR-0012). В SS14 эту связь держит разум (`MindComponent`): отдельная сущность, у которой
есть владелец-игрок (`UserId`), тело (`OwnedEntity`) и сущность, которую игрок временно
«посещает» (`VisitingEntity`, например призрак, из которого можно вернуться в тело). Тело
знает свой разум через `MindContainerComponent`. На разуме держатся призраки, возвращение
в тело, наблюдатели, итоги раунда, осмотр («кататоник», «SSD»), а позже — роли, цели и
антагонисты.

## Решение

1. **Разум — сущность** с `MetaData` и компонентом `Mind`, без `Transform`: в мире её нет,
   PVS её не видит, клиентам она не передаётся (в SS14 разум уходит только своему игроку
   через `PvsOverride`; клиенту он пока не нужен). Удаление раунда (`FlushEntities`)
   удаляет разумы вместе с остальным; перед этим `RoundRestartCleanup` стирает их, как
   `WipeAllMinds` SS14, чтобы удаление тел не порождало призраков.
2. **Словарь «пользователь → разум»** — ресурс `Minds` (`UserMinds` SS14). Сессия
   находится по `UserId` среди сущностей `Session`.
3. **Перенос, посещение, стирание** (`TransferTo`, `Visit`, `UnVisit`, `WipeMind`,
   `SetUserId`, `ControlMob`) повторяют SS14 вместе с событиями (`MindAddedMessage`,
   `MindRemovedMessage`, `MindUnvisitedMessage` и парные на разуме). Тело без разума после
   удаления становится призраком (`GhostOnShutdown`), если раунд не в лобби.
4. **Роль наблюдателя** до системы ролей — флаг `observer` в разуме (вместо
   `MindRoleObserver`). Имена игроков для итогов (`ContentPlayerData.Name`) остаются в
   `GameTicker`: они живут и после выхода игрока.

## Последствия

- `GameTicker` больше не хранит тела: вернувшийся игрок получает текущую сущность своего
  разума, а без неё становится наблюдателем — как `PlayerStatusChanged` SS14.
- Роли, цели и антагонисты (фаза 7) лягут в разум без изменения связи игрока с телом.
