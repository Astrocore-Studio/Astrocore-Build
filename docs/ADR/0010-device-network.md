# ADR-0010. Сеть устройств: типизированные пакеты-события и ссылки на устройства из карты

Дата: 2026-11-27. Статус: **принято** (исполнитель по плану фазы 5, задача 5.6б).

## Контекст

Воздушные и пожарные тревоги SS14 @ 2f4a2aad управляют вентиляциями, скрубберами,
датчиками и пожарными шлюзами через сеть устройств (`DeviceNetworkSystem`):

- устройство (`DeviceNetworkComponent`) входит в сеть по номеру (`deviceNetId`: `Wired`,
  `Wireless`, `Apc`, `AtmosDevices`…), получает случайный адрес и слушает частоту из
  прототипа `deviceFrequency`;
- пакет (`DeviceNetworkPacketEvent<T>`) — событие с типизированными данными `T`, адресом
  или широковещательный; отправка сразу, без очереди;
- вид сети решает, дойдёт ли пакет (`BeforePacketSentEvent`): проводная — тот же грид,
  беспроводная — та же карта и дальность, сеть APC — та же сеть APC;
- список устройств (`DeviceListComponent`) — кого тревога знает и кому шлёт; на карте
  Saltern это 44 списка с номерами сущностей файла карты.

У нас карта уже хранит непонятные игре поля известных компонентов как были
(`MapPreserved.fields`) и сообщает соответствие «номер в файле → сущность» событием
`MapLoaded` (так переносятся декали).

## Решение

1. **Пакет — обычное событие движка с типом данных**: `DeviceNetworkPacket<T>` поднимается
   на получателе, как `DeviceNetworkPacketEvent<T>` в SS14. Словарей «ключ → объект» нет:
   каждая система объявляет свой тип данных (`AtmosSyncPayload` и т. п.).
2. **Сети — ресурс сервера** по номеру сети: адреса, слушатели по частоте, «слушающие всё»
   — как `DeviceNet`. Адреса случайные из генератора мира, формат `XXXX-XXXX` с префиксом
   из перевода.
3. **Виды сети — подписчики `BeforePacketSent`** с теми же правилами: проводная (грид),
   беспроводная (карта и дальность), APC (одна сеть узлов у поставщика питания).
4. **Ссылки на устройства из карты** (`devices` списка устройств, позже связи сигналов)
   разбираются после загрузки по `MapLoaded` из сохранённых как были полей. При сохранении
   карты эти поля пишутся как были загружены: изменения списков в игре в файл карты пока не
   попадают (это задача маппинга с настройщиком сети, `NetworkConfigurator`).
5. **Связи сигналов (`DeviceLinking`) и настройщик сети** — отдельными частями: тревогам
   они не нужны.

## Последствия

- Любое устройство SS14 с сетью переносится подпиской на `DeviceNetworkPacket<СвойТип>`.
- Тесты собирают сеть без карты, ссылки из карты проверяются загрузкой Saltern.
