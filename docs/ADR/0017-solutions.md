# ADR-0017. Растворы: как в SS14 — компонент на сущности и сущности-растворы в контейнере

Дата: 2026-11-28. Статус: **принято** (исполнитель по плану фазы 7, задача 7.2).

## Контекст

Химия SS14 @ 2f4a2aad строится на растворе (`Solution`): список «реагент → количество» с
наибольшим объёмом, температурой и флагом «может реагировать». Где растворы живут:

1. **Основной раствор сущности** — компонент `Solution` на ней самой (`SolutionComponent`:
   имя `id` и раствор `solution`). Мензурка — сущность с раствором `beaker`, шприц — с
   `injector`. Поле `solution` наследуется со слиянием (`AlwaysPushInheritance`): у мензурки
   имя приходит от одного родителя, вместимость 60 — от другого.
2. **Дополнительные растворы** — отдельные сущности-растворы (прототипы с `Solution`) в
   контейнере `solutions`. Их создаёт `SolutionManager` при появлении сущности (по списку
   прототипов) или `EnsureSolution` по запросу системы (кровь, желудок). Сущность-раствор
   знает своего хозяина (`ContainedSolution`), хозяин держит кэш «имя → сущность».
3. Поиск раствора по имени (`TryGetSolution`) сначала смотрит свой компонент, потом кэш.
   Компоненты-возможности (`RefillableSolution`, `DrainableSolution`, `DrawableSolution`,
   `InjectableSolution`, `ExaminableSolution` и др.) указывают имя раствора.
4. Каждое изменение раствора проходит `UpdateChemicals`: реакции, перелив сверх
   вместимости (`SolutionOverflowEvent`), событие `SolutionChangedEvent` хозяину, вид
   заполнения (`SolutionContainerVisuals`).

Данные реагента (`ReagentData`) — список при реагенте; в SS14 есть один вид, `DnaData`
(ДНК в крови). Реагенты с разными данными — разные записи раствора.

До 7.2 кровь (ADR-0016) и вдох лёгких (ADR-0009) хранились списками без растворов.

## Решение

1. **Раствор переносится как в SS14:** тип `Solution` с теми же правилами деления
   (`SplitSolution` в сотых долях, «округление в пользу берущего»), слияния с теплоёмкостью
   (`AddSolution`), удаления, масштабирования, основного реагента и смешанного цвета.
   Теплоёмкость считается по прототипам реагентов при надобности (без кэша с «грязным»
   флагом: растворы маленькие, а кэш в SS14 — источник плавающих ошибок).
2. **Где живут растворы — как в SS14:** компонент `Solution` на сущности (с наследованием
   поля `solution` со слиянием) и сущности-растворы в контейнере `solutions` под
   `SolutionManager`. Так прототипы и карты SS14 читаются без переделки, а системы
   обращаются к раствору по имени так же, как в SS14 (`try_get_solution`).
3. **Данные реагента** — перечисление `ReagentData` с одним вариантом `Dna`; в данных —
   `!type:DnaData`.
4. **Каждое изменение — через `update_chemicals`:** реакции (с 7.2б), перелив, событие
   изменения хозяину, вид заполнения. Растворы передаются клиенту компонентом.
5. **Кровь и лёгкие переходят на растворы в 7.2в** (растворы `bloodstream`,
   `bloodstreamTemporary`, `chemicals`/`metabolites`, раствор лёгких), когда появится
   метаболизм; до этого списки ADR-0009 и ADR-0016 остаются.

## Последствия

- Сущностей становится больше: у тела — растворы крови, желудка и т. п. На 160+ игроков
  это сотни сущностей без отдельных систем такта; растворы обновляются только при
  изменении.
- Мензурки, шприцы и машины химии из прототипов SS14 работают без своих таблиц.
- Компонент старого вида `SolutionContainerManager` (в прототипах SS14 не встречается) не
  переносится.
