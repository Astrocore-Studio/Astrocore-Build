# ADR-0006. Данные карты вне компонентов: декали и чанк-сущности

Дата: 2026-11-26. Статус: **принято** (исполнитель по плану фазы 4, задача 4.4).

## Контекст

Карты SS14 @ 2f4a2aad хранят декали не в компоненте грида, а в «чанк-сущностях» вне карт
(`ChunkEntity` + `DecalChunk`, чанк 16×16 клеток, Robust @ 1afd692); грид перечисляет их в
`ChunkContainer`, чанк-сущность ссылается на грид полем `root`. Старые карты (около сотни в
upstream) хранят декали в компоненте грида `DecalGrid`, который SS14 только читает. Ссылки
между сущностями в этих компонентах — номера сущностей файла.

Движок (ADR-0015 Engine) сохраняет карту сам: компоненты из реестра пишет отличиями от
прототипа, непонятые компоненты — как были прочитаны (`MapPreserved`), а сущностям оставляет
номера из файла (`MapFileEntity`), поэтому ссылки в непонятых компонентах остаются верными.
Но декали надо рисовать на клиенте и менять в игре, а ссылки на новые гриды и новые чанки
движок не знает.

## Решение

1. **В игре декали грида — один сетевой компонент `GridDecals`** (Build, `decals.rs`): ключ —
   чанк и номер в чанке, как в SS14. Он не регистрируется как компонент данных и в файл
   напрямую не попадает. Клиент рисует декали по нему (`decal_visuals.rs`).
2. **Чтение — по событию движка `MapLoaded`**: декали берутся из чанк-сущностей файла и из
   старого `DecalGrid`. Исходные записи остаются в `MapPreserved` до сохранения: сохранение
   без шага 3 не теряет декали.
3. **Запись — шаг игры перед сохранением** (`decals::write_for_save`, его вызывают `savemap` и
   проверка `check_map`): чанк-сущности переписываются в формате `DecalChunkDecalsSerializer`
   (группы по общим полям, номера по возрастанию), новые получают следующий свободный номер
   файла, пустые удаляются, грид получает `ChunkContainer` с номерами чанков; `DecalGrid`
   заменяется чанк-сущностями, как при загрузке в SS14.
4. **Порядок и формат — как в SS14**, чтобы пересохранённая карта upstream отличалась от
   оригинала только там, где её меняли: Saltern пересохраняется с теми же декалями байт в байт.

## Последствия

- Любой путь сохранения карты из игры должен вызывать `write_for_save`; иначе в файл уйдут
  декали на момент загрузки (без правок, но и без потерь).
- Другие данные SS14 в чанк-сущностях (если появятся) сохраняются как были: шаг 3 трогает
  только `ChunkEntity` и `DecalChunk`.
- Тот же приём (сетевой компонент в игре + запись в формат SS14 перед сохранением) годится
  для следующих данных карты со ссылками между сущностями, пока движок не умеет ссылки в
  компонентах данных.
