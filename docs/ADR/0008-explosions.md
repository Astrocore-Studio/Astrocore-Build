# ADR-0008. Взрывы: заливка клеток грида и обработка по тактам, как в SS14

Дата: 2026-11-27. Статус: **принято** (исполнитель по плану фазы 5, задача 5.9).

## Контекст

Взрыв SS14 @ 2f4a2aad (`ExplosionSystem` и части `TileFill`, `Airtight`, `GridMap`,
`Processing`, `Visuals`; `ExplosionTileFlood`, `ExplosionGridTileFlood`,
`ExplosionSpaceTileFlood`; `ExplosionPrototype`, `ExplosiveComponent`) работает в два этапа:

1. **Заливка**: от клетки эпицентра волнами расходится по клеткам. Каждая волна —
   «итерация» с общей силой на клетку; общая сила взрыва (`totalIntensity`) распределяется
   по итерациям шагом `slope / 2`, сила клетки не выше `maxIntensity`. Соседи по сторонам
   добавляются через две итерации, по диагонали — через три. Непроницаемые сущности
   (`Airtight`) задерживают волну в своих направлениях на столько итераций, сколько нужно,
   чтобы взрыв их разрушил (`GetExplosionTolerance` по порогам `Destructible`); неразрушимые
   не пускают совсем. Взрыв на гриде переходит в космос и на другие гриды через «края»
   гридов с переводом координат.
2. **Обработка**: по итерациям от центра, не больше `explosion.tiles_per_tick` клеток и
   `explosion.max_tick_time` мс за такт: каждой сущности клетки — урон
   `damagePerIntensity × сила` (с поправками `ExplosionResistance`), незакреплённые тела
   отбрасываются, пол ломается с вероятностью по кривой прототипа до базового тайла.

Разрушение сущностей от урона (`DestructibleSystem`) у нас ещё не перенесено, а взрыв
опирается на него: от порогов зависит и разрушение стен, и задержка волны.

У нас грид многоэтажный (ADR-0003), взрыв в SS14 — плоский.

## Решение

1. **Сначала `Destructible`** (5.9а): пороги урона и поведения SS14 (`DoActs`, обломки,
   звук, смена узла строительства, взрыв, опустошение контейнеров, газ). Без него взрыв
   ранил бы, но ничего не разрушал.
2. **Заливка — по алгоритму SS14** с теми же числами и порядком (итерации, шаг `slope / 2`,
   задержки сторон и диагоналей, задержка на преградах по их стойкости). Стойкость преград
   считается по клеткам, до которых дошла волна, в момент взрыва, а не хранится картой
   `ExplosionAirtightGrid` на каждом гриде: взрывы редки, а карту пришлось бы держать в
   согласии с каждым уроном стен.
3. **Одна система координат на взрыв**: клетки грида эпицентра, включая пустые клетки
   (космос рядом со станцией). Взрыв в открытом космосе — клетки карты. Переход волны на
   другой грид (стыковка шаттлов) пока не переносится; это отмечается в остатках фазы.
4. **Этажи независимы**: взрыв идёт по этажу эпицентра, как газ (ADR-0007). Вертикальное
   распространение — отдельным решением вместе с люками и лестницами.
5. **Обработка по тактам с бюджетом** — как в SS14 (`explosion.tiles_per_tick` = 100,
   `explosion.max_tick_time` = 7 мс, `explosion.single_tick_area_limit` = 400), чтобы
   большие взрывы не останавливали сервер при 160+ игроках. Взрывы встают в очередь,
   соседние одного вида сливаются (`MaxCombineDistance`).
6. **Вид**: клиент получает сущность взрыва с клетками и силой итераций и рисует огонь по
   клеткам (`ExplosionVisuals`), как в SS14; звук — на сервере.
7. **Части задачи**: 5.9а — `Destructible`; 5.9б — заливка, обработка, взрывчатка
   (`Explosive`, `ExplodeBehavior`), консольная команда для проверки; 5.9в — вид на
   клиенте.

## Последствия

- Любая система, которой нужно взорвать, вызывает `explosion::queue_explosion` или
  `trigger_explosive`, а не наносит урон по площади сама.
- Разрушенные стены меняют узел строительства (балка), разрушенные тайлы — на базовый
  тайл; атмосфера пересчитывает клетки через существующие события смены тайла и
  непроницаемости, разгерметизация после взрыва происходит сама.
