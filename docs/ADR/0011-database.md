# ADR-0011. База данных: sqlx, SQLite и PostgreSQL, запросы вне такта

Дата: 2026-11-27. Статус: **принято** (исполнитель по плану фазы 6, задача 6.1).

## Контекст

SS14 @ 2f4a2aad хранит игроков, выданные гостям идентификаторы, журнал подключений, сервера и
раунды, профили, баны, журнал действий администраторов в базе (`Content.Server.Database`,
EF Core). Движок базы выбирается настройкой `database.engine`: SQLite (по умолчанию, файл
`preferences.db` в каталоге данных) или PostgreSQL. Все запросы асинхронные: игра не ждёт базу
в такте, продолжение выполняется в основном потоке. Схема меняется миграциями — отдельными
для каждого движка.

План (6.1) уже решил: SQLite для разработки, PostgreSQL для продакшна, как в SS14. Сервер
рассчитан на 160+ игроков: подключения, профили и журнал не должны тормозить такт.

## Решение

1. **Библиотека — `sqlx`** (асинхронная, SQLite и PostgreSQL, миграции). Запросы — строки SQL с
   параметрами `$1…`, без проверки на этапе сборки: сборка не требует живой базы.
2. **Один код запросов для обоих движков** через `AnyPool`. Поэтому типы столбцов — только
   переносимые: целые — `BIGINT`, дробные — `DOUBLE PRECISION`/`REAL`, логические — `BIGINT`
   0/1 (драйвер `Any` не читает логический тип SQLite), UUID и адреса (подсети `адрес/префикс`)
   — текст, время — миллисекунды UTC (`BIGINT`). Миграции — две папки, `migrations/sqlite` и
   `migrations/postgres`, с одинаковыми таблицами и столбцами (как две ветки миграций SS14).
   Таблицы и столбцы названы как в SS14 (`player`, `assigned_user_id`, `connection_log`,
   `server`, `round`, `player_round`).
3. **Запросы вне такта.** Ресурс `Database` держит пул и фоновый рантайм `tokio`. Игра запускает
   задачу и передаёт продолжение `FnOnce(&mut World, результат)`; готовые продолжения
   выполняются в начале такта. Тесты ждут результат прямо (`block_on`).
4. **Подключение игрока** — по образцу `ConnectionManager` SS14: на `PlayerConnecting` решение
   откладывается; задача выдаёт гостю постоянный идентификатор по имени
   (`game.persistguests`), проверяет, пускать ли (баны — следующей частью), пишет журнал
   подключений и запись игрока и затем впускает или отказывает (ADR-0017 движка).
5. **Без базы** (тесты систем, клиент) подключение работает как раньше: ресурс `Database` не
   вставлен — решение не откладывается.

## Последствия

- Схема не совместима с базой SS14 побайтно (типы времени и UUID другие), но таблицы и смысл
  столбцов те же — перенос данных возможен скриптом.
- PostgreSQL проверяется вручную (в юнит-тестах — SQLite в памяти); обе папки миграций
  меняются вместе.
