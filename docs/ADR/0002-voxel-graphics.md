# ADR-0002. Воксельная графика Build

Дата: 2026-11-18. Статус: **принято** (владелец проекта, 18.11.2026).

## Контекст

Сущности Build (персонажи, одежда, предметы, мебель) нарисованы спрайтами SS14. Решено перейти
на полностью воксельную графику: сущности — воксельные модели, тайлы и структурная сетка
остаются. Воксельных моделей нет, художника под них пока тоже. Формат, импорт и сборку меша дал
движок (Engine ADR-0011, крейт `astrocore-voxels`).

Прототип конвертера (18.11.2026) показал: из четырёх направленных спрайтов (S, N, E, W) вырезается
настоящая объёмная модель (персонаж в форме выглядит трёхмерным), из одной картинки — выдавленная
(предметы, шкафы); у вещей с одной картинкой видна нарисованная «крышка» спрайта.

## Решение

1. **Масштаб 32 вокселя на метр** — один воксель на пиксель спрайта, конвертация без потерь.
   Перед модели смотрит в +Z, опора — центр основания (как в движке).
2. **Модели — данные.** Файлы `.avox` лежат рядом с текстурами: `assets/ss14/Models/<набор RSI>/<состояние>.avox`
   (`.flat.avox` — лежащая вещь), по картинке спрайта; манифест рендера сам подхватывает модель, если файл
   есть (уточнено при реализации 18.11.2026: модель — на картинку, а не на прототип, их делят много прототипов). Ручная модель
   (из MagicaVoxel `.vox` через импорт движка или из будущего редактора Studio) заменяет
   сгенерированную правкой одного поля — код не знает, откуда модель.
3. **Конвертер спрайт → воксели** — инструмент Build (`tools`):
   * четыре направления — пересечение силуэтов спереди, сзади и с боков, цвет грани — с её
     стороны;
   * одно направление — выдавливание: предметы тонко (порядка 4–6 вокселей), мебель и устройства
     глубже; цвет боков и верха — изнутри силуэта, без тёмной обводки; нарисованная крышка спрайта
     отрезается и становится настоящим верхом (доработка);
   * результат кладётся в `content/models` и правится или заменяется руками.
4. **Персонаж слоями.** Тело и каждый надетый предмет — свои модели, поверх друг друга, как
   нынешние слои с толщиной (`WornVolume`). Анимация частями (руки, ноги) — отдельное решение;
   до него — покачивание при ходьбе.
5. **Переход постепенный.** Пока у прототипа нет модели, рисуется спрайт (как сейчас). Клиент
   рисует модель, если она есть.

## Порядок работ

1. Рендер воксельной модели в движке: компонент, кэш сеток по модели, материал с цветом вершин,
   направление сущности.
2. Конвертер как инструмент Build и прогон контента (предметы, мебель, одежда, тело).
3. Клиент Build: модели для предметов и мебели, затем слои персонажа.
4. Редактор вокселей в Studio.

## Последствия

* Спрайты остаются исходником и запасным вариантом, пока модели не заменят их везде.
* Сгенерированные модели угловаты; хорошие модели — работа художника в редакторе.
* Размер репозитория растёт на файлы моделей (сжаты RLE; модель 32³ — единицы КиБ).
