# План: лобби и персонализация персонажа (как в SS14)

Состояние на сегодня: лобби есть (`gameplay/src/lobby.rs`: таймер, «Готов», «Присоединиться», чат отдельным модулем), персонаж один и безымянный, тело — `Mobs/Species/Human/parts.rsi`, одежда накладывается слоями (`apps/client/src/outfit.rs`), должность выбирается списком уже на станции. Профилей, слотов, внешности, приоритетов должностей, сохранения нет.

Эталон — SS14: `HumanoidCharacterProfile`, `HumanoidCharacterAppearance`, `PreferencesManager`, `LobbyGui`, `HumanoidProfileEditor`, `GameTicker.AssignJobs` (из `/home/user/astronre/space-station-14`).

## Что берём из SS14

| Часть | Поля и правила SS14 |
|---|---|
| Профиль | имя, возраст, пол и гендер (местоимения), вид, голос, описание (`FlavorText`), внешность, предпочтение одежды (`Jumpsuit`/`Jumpskirt`) и рюкзака (рюкзак, сумка, вещмешок), приоритет места появления |
| Внешность | цвет кожи, цвет глаз, причёска и борода (стиль и цвет), маркировки (позже) |
| Должности | на каждую `High` / `Medium` / `Low` / `Never`; одна `High` на профиль; раздача на старте по приоритетам и заявкам |
| Слоты | до N профилей на аккаунт (`MaxCharacterSlots`), выбранный слот, создать / удалить / копировать |
| Проверка | `EnsureValid`: длина имени и описания, допустимые стили и цвета, вид из списка, возраст в пределах вида |
| Лобби | `LobbyGui`: кнопки «Готов / Не готов», «Персонаж», «Наблюдать», информация о раунде и станции, чат, список игроков с готовностью, превью персонажа |

## Этапы

Каждый этап — отдельный коммит с тестами, правкой README и проверкой на экране.

### Этап 1. Профиль и внешность (основа)
- `crates/gameplay/src/character.rs`: `Profile` (имя, возраст, пол, внешность, предпочтения), `Appearance` (кожа, глаза, причёска, борода и цвета), `validate()` по правилам SS14.
- Данные причёсок и бород: каталог из `Mobs/Customization/human_hair.rsi` и `human_facial_hair.rsi` (имена состояний → стили), список генерирует скрипт `scripts/gen_customization.py`; текстуры тянем из форка (`sync-sprites`), `_NC` не трогаем.
- Тесты: проверка полей, обрезка длины, неизвестный стиль заменяется на значение по умолчанию.

### Этап 2. Показ внешности в мире
- Слои тела (`parts.rsi`) красятся цветом кожи; глаза, причёска, борода — слои поверх (порядок слоёв гуманоида SS14).
- Внешность каждого игрока реплицируется всем (`build.appearance`, интерес `Everyone`), клиент собирает спрайт из профиля в `players.rs`/`outfit.rs`.
- Тест: профиль → набор слоёв и цветов; скриншот двух персонажей с разной внешностью.

### Этап 3. Редактор персонажа и превью
- Окно «Персонаж» из лобби (по `HumanoidProfileEditor`): имя (с кнопкой «случайно»), возраст, пол, цвета (кожа, глаза), стили причёски и бороды, одежда и рюкзак, описание. Слева — превью с поворотом на 4 стороны.
- Сервер всегда проверяет профиль: клиент шлёт `char.save`, сервер валидирует и отвечает принятым вариантом.
- Тест: окно открывается и принимает ввод (headless egui), сервер отбрасывает недопустимое.

### Этап 4. Слоты и сохранение
- Хранилище профилей на сервере (файл JSON в каталоге данных, ключ — идентификатор клиента: `astrocore-persistence` или простой файл на старте), версии формата и миграция.
- Список слотов в редакторе: выбрать / создать / удалить; выбранный профиль уходит в раунд.
- Тест: запись и чтение, слот не пропадает после перезапуска, битый файл не роняет сервер.

### Этап 5. Приоритеты должностей и раздача
- Вкладка «Должности»: по каждой должности `High / Medium / Low / Never`, группировка по отделам (как в SS14).
- Раздача на старте раунда по `AssignJobs`: сначала `High`, потом `Medium`, `Low`; счётчики мест; игрок без заявок получает запасную должность (ассистент).
- Появление с именем и внешностью профиля; имя попадает в чат, ID-карту и КПК; одежда и рюкзак по предпочтениям.
- Тест: алгоритм раздачи на наборах заявок (приоритеты, нехватка мест), имя на карте.

### Этап 6. Лобби как в SS14
- Макет `LobbyGui`: слева панель персонажа и превью, справа чат лобби и список игроков с готовностью, внизу «Готов / Персонаж / Наблюдать».
- «Наблюдать» — призрак без должности; «Присоединиться» после старта — окно позднего входа со списком должностей и счётчиками.
- Тест: лобби-логика (готовые, наблюдатели, поздний вход), скриншоты.

### Позже (не в этом плане)
Маркировки, черты (`Traits`), снаряжение по должности (`Loadouts`), антагонисты, виды кроме человека, голос и звуки эмоций, расширенная проверка описаний.

## Что нужно решить до начала

1. **Хранение профилей.** Без аккаунтов ключ — идентификатор клиента (токен, лежащий у игрока) или имя? От этого зависит вход с другого компьютера.
2. **Число слотов.** По умолчанию в SS14 — 10; нам хватит и 3–5 на старте?
3. **Что в первом срезе.** Предлагаю этапы 1–3: имя, внешность, редактор и превью, без сохранения и должностей — это быстрее всего даст видимый результат; сохранение и приоритеты — следом.
4. **Виды и пол.** Только человек, мужчина / женщина / не определено (как в SS14)?
5. **Текстуры.** Причёски и глаза берём из форка (`Mobs/Customization`), он ванильный по этим файлам; `_NC` не трогаем.

## Риски
- Спрайт персонажа собирается на клиенте из слоёв, а слоёв станет заметно больше (кожа, глаза, причёска, борода, одежда): нужен кэш собранных кадров на профиль.
- Профиль — данные игрока: на сервере всё проверяется, клиенту не доверяем (длина имени, допустимые идентификаторы, цвета).
- Размер лобби и компонентов в сети ограничен (`LOBBY_MAX_BYTES`): превью строится у клиента из профиля, а не из картинок.
