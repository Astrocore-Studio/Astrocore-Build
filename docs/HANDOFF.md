# Промпт для продолжения работы: перенос контента SS14 в Astrocore Build

Ты продолжаешь работу над **Astrocore Build** — нейтральной базовой игрой, которая **точно переносит механики Space Station 14** на движок Astrocore (Rust, Bevy 0.20, сервер авторитетный). Ничего не придумывай сама: каждую механику сначала найди в исходниках SS14 и повтори их поведение и числа. Если в исходниках чего-то нет или в билде нет нужной системы, скажи об этом прямо, а не пропускай молча.

## Репозитории и пути

- Старые рабочие копии SS14 (для генераторов): `/tmp/ss14full/repo` (sparse, файл за файлом: `git sparse-checkout add /путь/к/файлу`) и `/tmp/ss14/repo`. Если их нет, используй клон AstroNRE.

## Жёсткие правила
1. Сообщения коммитов **на русском**, в конце только строка `Co-Authored-By: <имя модели> <noreply@anthropic.com>`. **Никаких ссылок на сессию или разговор** в коммитах.
2. Пуш: `git push origin HEAD:main`. Pull request не создавать.
3. Перед коммитом: `cargo fmt --all`, `cargo clippy --workspace --all-targets` без единого предупреждения, `cargo test -q --workspace` зелёный.
4. Сервер авторитетный: клиент только шлёт команды (`CMD_*` в `crates/gameplay/src/wire.rs`) и рисует то, что реплицировано.
5. Не закрывай пробелы словами «не перенесено» и не пропускай. Если перенести нельзя (нет системы), скажи честно и перечисли.
6. Звуки и спрайты берутся только из SS14 с проверкой лицензии: CC0, CC-BY, CC-BY-SA приемлемы; NC и «Custom» нельзя, кроме явно разрешённых владельцем (сейчас одно исключение: `soda_shake.ogg`).
7. Временные правки карты и отладочные файлы не коммитить.
8. Содержимое генерируется скриптами из SS14: не правь `content/prototypes/*.ron` вручную, правь генератор и запускай его заново.

## Устройство проекта
- `crates/gameplay/src/` — игровая логика: `module.rs` (главное состояние `State`, тик, команды), `handlers.rs` (цепочка `InteractionHandler`), `wire.rs` (команды, регистрация реплицируемых компонентов), `body.rs` (тело, метаболизм, температура, статусы), `chem.rs` (реагенты, реакции), `health.rs`, `reagents.rs` (`Solution`), `chemlab.rs` (смесители, плитка, ХимМастер), `cryo.rs`, `defib.rs`, `fx.rs` (подсказки и звуки), `dispenser.rs`, `analyzer.rs`, `idconsole.rs`, `electric.rs`, `piping.rs`, `tests.rs` (интеграционные тесты).
- `crates/atmos` — газы и трубы (`pipes.rs`: насосы, вентили, фильтр, термомашины, баллоны, криокапсула).
- `crates/tools` — `import-map` (карта SS14 → наш формат) и `sync-sprites`.
- `apps/client` — клиент (Bevy + egui): `hud.rs` окна, `lib.rs` системы, `sounds.rs`, `statusfx.rs`, `lights.rs`. `apps/server` — сервер.
- `content/prototypes/*.ron` — **сгенерированное** содержимое. `assets/ss14/` — текстуры, звуки, `render-manifest.json`.
- `scripts/` — генераторы: `gen_items.py` (предметы), `gen_chem.py` (реагенты, реакции, статусы), `gen_chem_machines.py`, `gen_spawners.py` (шкафы, раздатчики), `gen_vending.py`, `gen_roles.py`, `gen_computers.py`, `gen_access.py`, `sync_audio.py`, общий загрузчик `ss14yaml.py`.

## Рабочий цикл переноса механики
1. Найти в SS14 прототип (YAML) и систему (C#): прочитай **исходник**, а не пересказ.
2. Если данные берутся из прототипов, расширь соответствующий генератор и перегенерируй `content/prototypes/*.ron`; прочитай результат глазами.
3. Реализуй в `gameplay` (состояние в `State`, разбор прототипа при создании, команды в `wire.rs`, обработчик в `handlers.rs`, окно в `apps/client/src/hud.rs`).
4. Добавь тест: интеграционный в `crates/gameplay/src/tests.rs` (есть `harness`, `command`, `spawn`, хелперы `peek`, `lab_view`, `cryo_view`) и/или модульный рядом с кодом.
5. Спрайты и звуки: добавь пути в sparse-checkout SS14, запусти `cargo run -q -p tools --bin sync-sprites -- <SS14>/Resources/Textures`, `python3 scripts/sync_audio.py <SS14>` и `cargo run -q -p server -- --write-manifest assets/ss14/render-manifest.json`.
6. Раздел в `README.md`, коммит, пуш.

## Команды
- Импорт карты: `cargo run -q -p tools --bin import-map -- <SS14>/Resources/Maps/saltern.yml /tmp/saltern.ron Saltern`.
- Сервер: `bash scripts/run_server.sh --map /tmp/saltern.ron`; клиент: `bash scripts/run_client.sh --autoplay`. Без экрана: `xvfb-run -a …`. Для снимков окна: `ASTRO_SHOT=<каталог>` (кадры 260 и 340), `ASTRO_OPEN_ID=<hex id объекта>` открывает окно машины; `ASTRO_MAP=<карта>` нужен и клиенту. Идентификаторы объектов карты: `0x10000000 + индекс в списке items`.
- Генераторы запускаются из корня репозитория: `python3 scripts/gen_chem.py <SS14>`, `python3 scripts/gen_items.py <SS14> <SS14>/Resources/Maps/saltern.yml`, `PYTHONPATH=scripts python3 scripts/gen_chem_machines.py <SS14>`.

## Подводные камни
- Команды дольше 2 минут уходят в фон; долгие задачи запускай фоном и проверяй вывод.
- Место на диске ограничено: каталог `target` легко разрастается (десятки ГБ). При нехватке места удали старые тестовые бинарники в `target/debug/deps` и `target/debug/incremental`.
- В sparse-checkout SS14 добавляются **файлы по одному** (`git sparse-checkout add /Resources/Audio/…/файл.ogg`); каталог целиком может не материализоваться.
- Опасно запускать `git grep` по всему дереву SS14 в частичном клоне: он очень долго подтягивает файлы. Используй `grep -r` по локальному клону AstroNRE.
- Контент SS14 берётся по снимку `910154a7` (для старых генераторов) или по актуальной сборке AstroNRE; следи, чтобы генераторы и код согласовывались по одной версии.
- Тесты, где игрок взаимодействует с предметами: держи объекты рядом с точкой появления (около (3,0.9,3)) и на высоте 0,9, иначе не пройдёт проверка дальности и видимости.

## Известные пробелы (бери по порядку важности)
- Остальные 18 видов компьютеров не функциональны (рисуются, но без логики).
- Криокапсула на Saltern пуста, пока атмосферный отсек не подключён; нужно проверить цепочку баллоны → насос → фильтр на карте и, возможно, дать способ начального наполнения.
- Огнезапоры: лампы и питание; оружие и охрана; взрыв баллона при перегрузке; огнетушитель; Утилизатор (Recycler); особые роли и имена.
- Эффекты реагентов, которые невозможно перенести без новых систем (26 штук): превращение, зомби-заражение, `DnaImprint`, нарколепсия, глаза, гниение, выносливость, иконки газовых тревог.
- Чата нет: статусы речи (`Muted`, `Stutter`, `OwO` …) хранятся, но ничего не меняют.
- Вид таблеток (спрайты 1–20) не выбирается: у предмета один спрайт на прототип.
- Идея (пока не начата, нужен выбор владельца): визуальный стиль как в 3D-демо SS14 — освещение с фонариком, подсказка под прицелом, лог событий, раскладка интерфейса.
