# Astrocore — игра на ядре сущностей

Сервер и клиент на ядре сущностей движка (ADR-0015 в Astrocore Engine). Прототипы, карты и
картинки читаются прямо из каталога `Resources` Space Station 14.

Сейчас работает: загрузка станции (по умолчанию Saltern), вход игроков по сети, ходьба со
столкновениями, отрисовка тайлов и спрайтов, сглаживание стен, окон и столов (`IconSmooth`),
свет с тенями и поле зрения, клавиши SS14 из `keybinds.yml`, фоновые звуки устройств, окна
устройств: клавиша E рядом с устройством открывает его окно через сервер.

Чего пока нет: игрок получает тело корги (внешность гуманоидов — задача 3.10); окна устройств
показывают заглушку, пока само устройство не перенесено; двери, предметы, руки и чат
переносятся по [плану](../docs/ROADMAP.md).

## Запуск

Положите рядом Engine и референс SS14:

```bash
scripts/fetch_engine.sh
```

```bash
scripts/fetch_reference.sh
```

Игра в одиночку (сервер работает в процессе клиента):

```bash
cargo station
```

Выделенный сервер и клиент:

```bash
cargo serve
```

```bash
cargo client -- --connect 127.0.0.1:7783 --name Urist
```

Управление — как в SS14: WASD, Shift — шаг, E — использовать устройство рядом. Свои назначения
клавиш кладутся в файл `keybinds.yml` в каталоге запуска (формат SS14).

## Консоль и карты

Клавиша `~` открывает консоль: команды выполняет сервер. Игроку с той же машины, что и сервер
(в том числе в `cargo station`), доступны все команды; остальным — нет, пока не перенесено
администрирование. У выделенного сервера команды вводятся прямо в его терминал.

| Команда | Что делает |
|---|---|
| `mapping [номер] [путь]` | новая карта или карта из файла на паузе и без `MapInit`; игрок становится админ-призраком |
| `loadmap <номер> <путь>` | загружает карту из файла на паузе |
| `savemap <номер> <путь> [true]` | сохраняет карту в каталог данных (`data/`); инициализированную — только с `true` |
| `addmap`, `rmmap`, `lsmap` | создать, удалить, список карт |
| `pausemap`, `unpausemap`, `querymappaused`, `mapinit` | пауза и инициализация карты |
| `tp <x> <y> [карта]`, `tpto <куда> [кого…]`, `tpgrid <грид> <x> <y> [карта]` | телепорт |
| `aghost` | выйти из тела админ-призраком или вернуться |

В маппинге F5 открывает палитру сущностей, F6 — тайлов, F8 — декалей; строка поиска берёт фокус по клику.
Выбранное ставится левой кнопкой (по клеткам или свободно), Shift — линией, Ctrl —
прямоугольником; средняя кнопка поворачивает, правая отменяет, P берёт сущность под курсором.
Ластик стирает сущность под курсором (на пустом месте — декали клетки), с Shift — всё в
протянутом прямоугольнике вместе с декалями.

Пути — как в ресурсах: `Maps/saltern.yml`. Файл ищется сначала в `data/`, затем в ресурсах игры.
`cargo run --release -p astrocore-game --example check_map` проверяет, что карта сохраняется и
загружается обратно без потерь.

## Настройка

| Что | Как |
|---|---|
| Каталог `Resources` SS14 | переменная `ASTRO_SS14_RESOURCES`; по умолчанию `../reference/space-station-14/Resources` |
| Свой контент поверх SS14 | каталог `Resources` в корне Build: его файлы важнее файлов SS14 |
| Язык | `ASTRO_LANG`, по умолчанию `en-US` (язык контента SS14); свой перевод кладётся в `Resources/Locale/<язык>` игры |
| Адрес сервера | `ASTRO_ADDR`, по умолчанию `127.0.0.1:7783` |
| Ключ соединений | `ASTRO_KEY`, 64 шестнадцатеричных символа; одинаковый у сервера и клиентов |
| Карта раунда | `game.map` в `server_config.toml`, например `"Maps/bagel.yml"` |
| Тело игрока | `game.player_prototype` в `server_config.toml` |
| Каталог данных (сохранённые карты) | `game.user_data`, по умолчанию `data` |
| Все команды игроку с той же машины | `console.loginlocal`, по умолчанию `true` |

Без `ASTRO_KEY` используется общеизвестный ключ: он годится только для игры на своём компьютере.
